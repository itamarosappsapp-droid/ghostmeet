# ScreenCaptureKit — бэкенд канала `Them` по умолчанию

**Заменяет в части дефолта захвата [ADR-0001](0001-swappable-backends-behind-protocols.md).**

Канал `Them` по умолчанию захватывается через **ScreenCaptureKit**, а не через Core Audio Process Tap. Тап остаётся вторым бэкендом и выбирается в настройках.

Это разворот исходного решения — спека и [ADR-0001](0001-swappable-backends-behind-protocols.md) ставили тап по умолчанию. Причина разворота измеримая: **SCK отдаёт сигнал в 1.5–2.5 раза громче** на одной и той же записи (`пик_rms` 0.095–0.127 против 0.051–0.081). Виновато пригибание громкости, которое включает эхоподавление микрофона: по тапу оно бьёт заметно сильнее. Ослабить его до конца не удалось даже минимальной настройкой.

Громкость здесь не косметика, и живое сравнение это показало жёстче, чем ожидалось. Одна и та же запись, одна модель, включённое эхоподавление:

| Бэкенд | Уровень | Распознано из одной реплики |
|---|---|---|
| ScreenCaptureKit | 0.1383 | **142 символа** |
| Core Audio Process Tap | 0.0488 | **3 символа** |

Разница в 2.8 раза по сигналу оказывается разницей между рабочим распознаванием и мусором. Никакая правка промптов столько не даёт.

## Почему исходное обоснование больше не работает

Спека выбирала тап по трём доводам, и к сегодняшнему дню уцелел один:

- «Чище: только выбранный процесс» — неверно. Обе технологии работают на уровне приложения, вкладку браузера не изолирует ни одна.
- «Узкое разрешение: Audio Capture вместо Screen Recording» — неверно для нашего сценария. Режим «Решить с экрана» требует записи экрана в любом случае, так что разрешение всё равно выдано.
- «Видит любой процесс со звуком» — **верно**. SCK перечисляет только оконные приложения; `afplay` в его списке не появляется никогда. Это и есть причина оставить тап вторым бэкендом, а не удалить.

## Consequences

- На свежей машине первый запуск упирается в разрешение на запись экрана — теперь это путь по умолчанию, а не запасной. Отсутствие разрешения обязано объясняться словами внутри окна, не системным баннером ([ADR-0004](0004-invisibility-scope.md)).
- Перечень приложений-источников зависит от бэкенда: у SCK свой, у тапа свой. Показывать список от одного бэкенда при выбранном другом — значит дать пользователю выбрать то, что не заработает.
- Захват неоконных источников (`afplay`, консольные утилиты) остаётся возможен только через тап. Для отладки это существенно: именно так проверяется звуковой конвейер без браузера.
- [ADR-0005](0005-vpio-and-process-tap-cannot-coexist.md) отменён и к этому решению отношения не имеет: тап исправен, дело было в ошибке работы с памятью, а не в несовместимости.
