# Версии и релизы

## Схема

[Семантическое версионирование](https://semver.org/lang/ru/): `MAJOR.MINOR.PATCH`, начиная с
**0.1.0**. Пока мажорная версия — ноль, ломающие изменения несёт **минорная**, всё остальное —
патч. Мажорная станет единицей не по достижению какого-то числа возможностей, а когда список v1.0
из [GhostMeet.md](GhostMeet.md) будет закрыт и формат настроек можно будет объявить устоявшимся.

Что считается ломающим в приложении без API: несовместимая миграция настроек, смена аккордов по
умолчанию, изменение состава разрешений, снятие провайдера или бэкенда захвата.

**Версии ниже 0.1.0 реконструированы задним числом.** Проект шёл без версий от первого коммита до
закрытия MVP; вехи разложены по `0.0.1`–`0.0.6` в [CHANGELOG.md](../CHANGELOG.md) и помечены
аннотированными тегами на тех коммитах, где эта работа легла. Это запись истории, а не выпущенные
сборки: DMG собирался только для `0.1.0`.

## Где живёт версия

`MARKETING_VERSION` в `GhostMeet/GhostMeet.xcodeproj/project.pbxproj`, во **всех четырёх**
конфигурациях: два таргета (приложение и тесты) × Debug/Release. Отдельного `xcconfig` нет
сознательно — его пришлось бы вносить в файл проекта руками, а pbxproj в этом проекте и так
единственное место, которое правится руками.

`CURRENT_PROJECT_VERSION` — номер сборки, растёт на единицу с каждым релизом. macOS сравнивает
именно его, а не человеческую версию.

Проверка согласованности стоит в трёх местах, и это не дублирование: `set-version.sh` не даёт
проставить версию частично, CI ловит расхождение версии с CHANGELOG на каждом push, а
`release.sh` отказывается выпускать релиз, если проект и запрошенная версия разошлись.

## Порядок выпуска

```bash
./scripts/set-version.sh 0.2.0     # версия в проекте + номер сборки
```

Дальше — раздел `## [0.2.0]` в [CHANGELOG.md](../CHANGELOG.md). Пишется он **не по списку
коммитов**: в заметках стоит то, что изменилось для человека, который запускает приложение, и
почему. Из него же берутся заметки к релизу на GitHub — два описания одного релиза разошлись бы на
первой правке.

```bash
git commit -am "Версия 0.2.0"
./scripts/release.sh 0.2.0
```

`release.sh` по шагам:

1. отказывается работать на грязном дереве — иначе тег указывает на один код, а DMG собран из
   другого, и расходятся они молча;
2. проверяет, что тега ещё нет, что версия в проекте совпадает с запрошенной и что раздел в
   CHANGELOG существует;
3. прогоняет тесты **до** сборки образа и отдельно ловит `Test run with 0 tests` — эта строка
   выглядит успехом, а означает упавший на старте host (см. CLAUDE.md);
4. зовёт `make-dmg.sh`: Release, проверка подписи, проверка всех четырёх строк разрешений,
   образ с приложением, ярлыком «Программы» и инструкцией;
5. ставит аннотированный тег с заметками из CHANGELOG;
6. **спрашивает**, прежде чем что-либо отправить наружу, и только потом делает push и создаёт
   релиз на GitHub.

Ключи: `--dry-run` — всё локально, наружу ничего; `--yes` — без вопроса, для повторного прогона.

Отменить неудачный выпуск до публикации: `git tag -d v0.2.0`.

## Что делает CI

[.github/workflows/ci.yml](../.github/workflows/ci.yml) на каждый push и pull request:

- собирает и прогоняет тесты на macOS-раннере с **ad-hoc-подписью** (`CODE_SIGN_IDENTITY=-`) —
  на Apple silicon неподписанный бинарник не запускается вовсе, а тесты хостятся внутри
  `GhostMeet.app`;
- отдельным шагом валит прогон на `Test run with 0 tests`;
- проверяет, что `MARKETING_VERSION` стоит во всех четырёх конфигурациях и что для этой версии
  есть раздел в CHANGELOG; на теге — что тег совпадает с версией внутри приложения.

CI **ничего не подписывает и не публикует**. Причина не в лени: разрешения macOS привязаны к
подписи, сертификат у проекта личный (Apple Development), и отдать его закрытую часть в secrets
значит разрешить подписывать этим именем всякому, кто получит доступ к репозиторию. Собирать же в
CI без настоящей подписи — значит отдавать коллегам сборку, которая заново спрашивает микрофон и
запись экрана при каждом обновлении.

**Известный риск первого прогона:** делегат на старте зовёт `recognition.prepare()`, то есть
приложение тянет модель WhisperKit. На раннере это сеть и минуты, а в худшем случае — падение
host-процесса, которое шаг «ноль тестов» покажет прямым текстом. Если так и выйдет, чинить это
надо в приложении (пропускать подготовку под тестами), а не ослаблением проверки в CI.

## Нотаризации нет

У проекта сертификат Apple Development, а не Developer ID, поэтому `spctl` сборку отклоняет и
каждому получателю нужна одна команда:

```bash
xattr -dr com.apple.quarantine /Applications/GhostMeet.app
```

Она напечатана и в выводе скрипта, и в файле внутри образа. Ad-hoc-подпись эту цену не убирает, а
добавляет свою: разрешения перестают переживать обновление.
