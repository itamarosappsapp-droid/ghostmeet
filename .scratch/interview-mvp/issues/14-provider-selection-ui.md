# 14 — Выбор провайдера в настройках

**What to build:** Пользователь выбирает провайдера из списка, правит при необходимости базовый адрес и модель, и вводит ключ — свой для каждого провайдера, потому что ключи разных сервисов должны лежать рядом, а не затирать друг друга.

Экран должен честно показывать, что умеет выбранный провайдер: текстовый он или принимает изображения. Это не косметика — от этого зависит, работает ли режим решения задачи с экрана в полную силу.

**Blocked by:** 12 — OpenAI-совместимый провайдер (нужен хотя бы один непустой транспорт помимо Anthropic).

**Status:** done

- [x] Провайдер выбирается из списка предустановок, выбор сохраняется между запусками
- [x] Базовый адрес, модель и команда CLI редактируются и переопределяют значения предустановки
- [x] Ключ хранится **свой на каждого провайдера**, все — в Keychain, ни один не попадает в настройки, файлы и логи
- [x] Для локальных провайдеров и CLI поле ключа не требуется
- [x] Экран показывает, принимает ли выбранный провайдер изображения, и предупреждает, что без этого режим решения задачи с экрана слабее

## Comments

**Ключ теперь свой на провайдера** — аккаунт в Keychain включает идентификатор предустановки. До этого ключ был один общий, и переключение с одного сервиса на другой затирало бы предыдущий. Есть миграция: ключ, сохранённый прежней версией, переезжает на выбранного провайдера при старте, причём старая запись удаляется только **после** успешной записи новой.

Замыкание чтения ключа пришпилено к тому провайдеру, который был выбран в момент сборки, — переключение не может отправить одному сервису ключ другого.

Проверка «ключи не утекают» усилена: разворачивается весь словарь настроек, ищутся оба ключа сразу и подстрока имени аккаунта, и **отдельно проверяется, что не-секретные поля в дампе есть** — иначе проверка проходила бы вхолостую на пустом хранилище.

**Экран не может соврать о возможностях.** Обещание интерфейса сверяется тестом с `capabilities` реально собранного провайдера по всем тринадцати предустановкам. Ошибка конфигурации (опечатка в адресе) показывается красной строкой рядом с полем, потому что строится попыткой собрать настоящего провайдера — экран не скажет «всё в порядке» о том, что сессия отвергнет.

**Два долга погашены сразу после ветки:** переопределение команды CLI применялось в хранилище настроек в обход фабрики (ветка не могла править `Intelligence/`) — перенесено в фабрику, где ему место. Мёртвый метод сборки провайдера Claude удалён.

**Требует ручной проверки:** экран настроек не прокликан вживую — оверлей неактивирующий, и без прав Accessibility агент не мог нажать шестерёнку. Проверены только инварианты окна и тесты.

**Мелочь на будущее:** в списке провайдеров не отмечено, у кого из них ключ уже сохранён — видно только про выбранного.
