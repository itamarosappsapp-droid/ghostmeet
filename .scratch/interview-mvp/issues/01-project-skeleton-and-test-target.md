# 01 — Скелет проекта и тестовый таргет

**What to build:** Проект получает структуру слоёв из спеки и тестовый таргет, в котором можно запускать тесты одной командой. После этого тикета любой следующий начинается с готового места, куда класть код и тесты, а не с перестройки проекта.

**Blocked by:** None — can start immediately.

**Status:** done

- [x] Каталоги слоёв созданы согласно структуре проекта из спеки
- [x] В проекте есть тестовый таргет на Swift Testing, связанный с основным таргетом
- [x] Команды запуска всех тестов и одного конкретного теста задокументированы в CLAUDE.md
- [x] Тесты проходят на чистой сборке
- [x] Артефакты сборки и пользовательские настройки Xcode не попадают в репозиторий

## Comments

Тестовый таргет `GhostMeetTests` добавлен правкой `project.pbxproj` вручную: новый `PBXNativeTarget` с типом `com.apple.product-type.bundle.unit-test`, своей синхронизированной группой, зависимостью от основного таргета и `TEST_HOST` на приложение.

Схема сделана **общей** (`xcshareddata/xcschemes/GhostMeet.xcscheme`) и закоммичена — автосхема Xcode лежит в `xcuserdata`, который в `.gitignore`, и на неё нельзя опираться при запуске тестов из командной строки.

Шаблонные `GhostMeetApp.swift` и `ContentView.swift` перемещены в `App/` и `UI/MainWindow/` через `git mv`. Пустые каталоги слоёв в git не попадают — это нормально, они наполняются по мере работы над тикетами.
